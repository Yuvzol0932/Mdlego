## 二、逐界面观察

### 1. 书架（01 有书 / 02 空）

**01 有书**
1. 文档卡片左侧那条竖线长度与卡片内容不等高：第一篇卡片内容 3 行，竖线只覆盖标题到摘要之间，卡片底部还留着一段空白，竖线与卡片底部没对齐。
2. 卡片之间是纯留白分隔，卡片本身没有背景/描边，只有左侧竖线；三张卡片竖线在同一条 x 轴上，但卡片内容左边界与顶栏标题「墨读」的左边界不一致（顶栏标题居中、卡片左对齐），视线在页面上找不到一条贯穿的左边线。
3. 「共 3 篇」计数行居中显示在列表下方，它与最后一张卡片的距离，和第一张卡片与顶栏之间的距离不相等。
4. 摘要文字 2 行后被截断成省略号，但「词根词缀速查表」那张卡的摘要直接从 `| 词根 | 含义 |` 这样的原始 Markdown 管道符号开始，没有剥掉表格标记。

**02 空态**
5. 「墨」字方框图标、标题「书架空着」、说明文字、按钮四者左右居中，但说明文字折成两行时第二行明显更短，形成一个凸字形文字块。
6. 空态内容整体偏上：顶部到图标约 1/4 屏空白，按钮下方到屏幕底部约 2/5 屏空白，上下不对称。
7. 右下角导入按钮（`+`）在有书与空态下位置相同，空态页面中央又有一个「导入文档」按钮，同一屏出现两个导入入口。
8. 两张截图里都能看到底部悬浮一个深色圆角气泡（导入失败提示），它压在「共 3 篇」和导入按钮上方，遮住列表底部。

### 2. 阅读页正文（03 杂志 / 04 夜间 / 05 纸面）

9. 三个主题的版式骨架完全一致（同一套间距、同一套层级），差异只在颜色——符合杂志风定版。
10. 一级标题「词根词缀速查表」下方那条粗横线，右端顶到屏幕右边缘、左端从正文左边距开始，左右不对称。
11. 二级标题（「高频词根」「代码示例」）左侧的红棕色短竖线，高度比标题文字略高，且与标题文字的间隙较窄，两者贴得紧。
12. 正文段落首行缩进两个字，但列表项、表格、代码块都不缩进；同一屏里缩进与不缩进混排。
13. 表格右列「备注」内容被截断（`拉丁 spe…`），表格横向滚动容器右侧有一条淡色渐变遮罩，遮罩较窄，`spect` 那行的截断处正压在遮罩上。
14. 代码块背景是浅灰圆角矩形，圆角半径与表格、引用块看起来一致；代码块内文字左内边距比正文左边距大，代码块本身又比正文窄，形成三层不同的左边界。
15. 夜间主题下代码块背景与页面背景明度差很小，代码块边界几乎看不出，只能靠文字颜色区分。
16. 夜间主题下正文与顶栏标题同为暖白，但表格分隔线是较暗的灰——同一界面里「字」与「线」的明度分三档。
17. 纸面主题背景冷白，杂志主题背景暖米色，两者正文文字却都是接近纯黑的深色；纸面下对比度明显更高。

### 3. 大字号档（06 / 07）

18. 字号档 7 时一级标题几乎占满整行宽度，标题与下方横线之间几乎无边距。
19. 大字号下表格只能显示 3 列（「备注」列完全滚出视野），第一列与第二列之间的间距比默认字号时更紧。
20. 大字号下行首缩进仍是两个字，但两个字随字号变宽，首行缩进量比默认字号大一截，右端因此更短。
21. 07 滚动后：顶栏覆盖在正文上，正文第一行紧贴顶栏下沿，没有额外留白，看起来像被切掉一截。

### 4. 目录抽屉（08）

22. 抽屉宽度约占屏幕 5/6，左侧露出一条被灰色遮罩压暗的正文。
23. 抽屉标题「目录」字号与正文二级标题接近，但抽屉标题是常规字重、正文标题是粗体——同为「标题」却两套字重逻辑。
24. 抽屉里文档标题「长篇阅读素材 · 痕迹」与下方五个章节标题之间，没有分隔线也没有额外留白，只靠缩进区分层级，而缩进量约一个字宽，层级不够明显。
25. 抽屉标题行与第一条内容之间的留白，比内容条目之间的留白小很多。
26. 抽屉右上角关闭是 `×`，而阅读页顶栏返回、设置页返回都是 `←`——同一「退出当前层」的动作在两处用了不同图标语义。

### 5. 搜索浮层（09 / 09b / 10）

27. 搜索浮层从顶部下拉，输入框圆角半径与页面其它圆角元素（代码块、按钮）不完全一致，看起来更圆。
28. 输入框右侧有一个 `×`（清空），紧邻外侧还有一个 `×`（关闭），两个图标相距很近、样式相近但作用不同。
29. 输入框聚焦时有红棕色描边（09），失焦时无描边（10）——同一浮层两种边框状态，且聚焦描边与二级标题竖线同色。
30. 「找到 3 处」用灰色小字左对齐，与命中条目文字左边界对齐，但它到上方输入框的距离与到下方第一条命中的距离不相等。
31. 命中条目之间用极浅分隔线，最后一条命中与浮层底边之间没有分隔线，浮层底部是一个大圆角切角。
32. 09 与 09b 的空态提示居中显示，但占用高度比有结果时矮很多，浮层高度随内容跳变。

### 6. 长文滚动（11 / 12）

33. 11 滚动中：顶栏是实色背景，正文从顶栏下沿直接被切断，没有渐隐或阴影过渡，切断处正好切在一行正文文字中间。
34. 12 末尾：正文最后一段之后约 1/6 屏空白才到工具栏，与段落之间的间距不等。
35. 底部工具栏固定，四个图标（书架/目录/搜索/设置）等距，图标与下方文字垂直间距较紧。
36. 工具栏上边缘那条极浅分隔线，与表格线、卡片竖线的颜色/粗细不完全一致。

### 7. 任务清单（13）

37. 勾选条目文字变灰并加删除线，未勾选为深色——状态区分明确。
38. 复选框是圆形，勾选后填充红棕色并显示白色对勾；圆形复选框与「待办清单」的常规方形视觉不同。
39. 每个条目左侧还有一个红棕色小圆点（列表项目符号），与圆形复选框并排，形成「点 + 圈」两个圆形紧邻。
40. 勾选后整行文字变灰，但左侧项目符号圆点颜色不变，一行里同时存在「已变灰的文字」和「未变灰的点」。
41. 引用块背景是浅灰圆角块，内部文字是斜体衬线，与正文正体衬线不同——同页两种字形。
42. 「主干是 `It is ... that ...` 强调句」里行内代码的灰底圆角块与正文基线不完全对齐，灰底略微偏下。

### 8. 表格 / 代码块（14 / 15）

43. 14：表头行下方是一条粗黑线，其它行之间是细灰线——粗细差异明显，但表头行上方的线与下方粗线之间没有区分。
44. 表格横向滚动时，右侧渐变遮罩与表格边框重叠处有一条竖直硬边。
45. 15：代码块与行内高亮（黄色底）同屏，黄色高亮圆角比代码块圆角小很多，两种圆角语言不同。
46. 行内代码（灰底圆角）与行内高亮（黄底）在同一段落里，灰底块内边距更大、更「鼓」，视觉重量不一致。
47. 二级标题「行内标记」的竖线与「代码示例」的竖线长度不同（前者更长），竖线没有按标题文字高度自适应，是固定长度。

### 9. 设置页（16）

48. 顶栏「←」在左、「设置」标题居中、右侧无对应元素——标题视觉重心偏左。
49. 分组标题「字体」「主题」是深色粗体小字，它与分组内容之间的间距比两个分组之间的距离小，分组归属靠间距推测。
50. 分段控件（宋体/黑体、杂志/夜间/纸面）是圆角胶囊，选中项是白色圆角块，白色块与胶囊边界的内边距左右不等（左侧更紧）。
51. 预览块是虚线边框 + 圆角，虚线密度较稀，与页面其它实线分隔线的视觉语言不同。
52. 版本信息块同样用虚线边框，内部 `dt`/`dd` 两列（灰字标签 + 深色值），两列之间没有基线对齐，`0.1.0` 与上一行标签的间距比 `buildId` 那组紧。
53. 「网络权限 / 未申请（完全离线）」与上面两组字段结构一致，但它表达的是安全声明而非版本信息，却放在同一个虚线框内。
54. 字号/行距/段间距三个 stepper 与「字体」分段控件的控件形态差异大（档位点 + 加减按钮 vs 胶囊分段），且 stepper 需要滚动才能看全。

## 三、跨界面的一致性问题（汇总观察）

55. 圆角半径不统一：代码块、表格容器、引用块、搜索输入框、分段控件胶囊、白色选中块、行内高亮——至少 4 种不同的圆角视觉量级。
56. 分隔线不统一：卡片左侧竖线（粗、红棕）、表格横线（细灰）、二级标题竖线（粗、红棕）、顶栏下边线（极细灰）、工具栏上边线（极细灰）、抽屉条目分隔（更浅）——颜色与粗细至少三档。
57. 「退出/关闭」图标不统一：阅读页与设置页用 `←`，抽屉与搜索用 `×`。
58. 标题字重不统一：一级标题粗体、二级标题粗体、抽屉标题常规、分组标题粗体小字。
59. 左侧对齐基准不统一：正文缩进 2 字、列表/表格/代码块不缩进、卡片左对齐顶到边距、空态居中。
60. 暖色（红棕）用途过载：卡片竖线、二级标题竖线、复选框填充、按钮描边、列表项目符号、搜索框聚焦描边——同一强调色承担了装饰、状态、交互三种语义。

## 四、审计过程中发现的、不属于视觉范畴的观察（仅记录）

- 该机 `adb shell input tap/keyevent` 全部被 MIUI 拦截（`SecurityException: INJECT_EVENTS`），真机操作改走 WebView DevTools CDP。
- 首次进入时界面残留一条「1 篇失败 · 没有读取该文件的权限…」toast，来源是早前失败的分享导入留下的待处理 URI；清空 `pendingUris` 后消失。这不算 UI 问题，但说明待处理 URI 失败后会在每次启动重试并弹提示。
- 路由切换（阅读页 → 设置页）时滚动位置被继承：阅读页滚到 `scrollY=372` 后进设置页，设置页同样停在 372，导致顶部三个 stepper 被滚出视野。

## 五、没有覆盖到的部分（如实说明）

- 排版浮层（`state.overlay === 'font'`）无界面入口：`views/settings.ts` 里有 `fontOnly` 渲染分支，但当前没有任何按钮能派发 `overlay/opened` + `font`，无法通过真实 UI 到达，未截图。
- 书架「有书」状态下超过一屏的长列表未覆盖，当前只有 3 篇。
- 删除确认、导入进行中、错误页等状态未覆盖——不在本轮指定清单内。
