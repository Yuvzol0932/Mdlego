# 阶段 E3 设计说明 · 备份与恢复

> 任务书 §6 E3：JSON 备份（文档、批注、进度、任务、设置、生词本），带版本号与校验；可选 WebDAV（凭据只存本机）。
> 本文记录格式契约、恢复语义与「不做 WebDAV」的理由。

## 1. 备份格式（本文写作时 schemaVersion 1；**阶段 E4 已升到 2**，新增 vocabulary 字段，v1 备份仍可恢复）

```json
{
  "format": "mdlego-backup",
  "schemaVersion": 1,
  "appVersion": "0.8.0",
  "exportedAt": "2026-11-17T12:00:00.000Z",
  "checksum": "fnv1a32:ab12cd34",
  "data": {
    "docs": [...], "marks": [...], "tasks": [...], "sessions": [...],
    "settings": {...}, "bookmarks": ["docId", ...]
  }
}
```

- **规范序**：`docs/marks/sessions` 按 `id`、`tasks` 按 `docId+bid+index`、`bookmarks` 按字符串排序，`settings` 保持键序。同一份数据两次导出的字节一致，便于 diff 与校验。
- **校验**：`checksum` = FNV-1a 32 over `JSON.stringify(data)`（同步、零依赖）。解包时重算比对，内容被改/复制不完整都会明确拒绝，绝不把半份数据写进本机。
- **版本**：`schemaVersion` 大于当前 → 直接拒绝（`备份来自更新版本的墨读，请先升级应用`），不做猜测式迁移；将来加字段必须升版本并写迁移。
- **生词本**：E4 还没做，数据结构不存在，**不写空占位**；E4 落地后在 schemaVersion 2 里加 `vocabulary`，旧备份仍可恢复（缺字段视为空）。

## 2. 导出路径：下载 + 剪贴板双保险

- 先尝试 `Blob` + `<a download>`（桌面 Chrome 可用；部分 WebView 的下载监听不可靠）。
- 同时把同一份 JSON 写剪贴板，toast 明确说明两条路径都给了：
  `备份已生成；若未出现下载，可从剪贴板粘贴保存`。
- 不做「保存到文件系统」：当前只有 Capacitor core + `@capacitor/app`，没有 Filesystem 插件；不为了预览版增加原生依赖。E6/后续可以再评估。
- 剪贴板写入失败时提示失败，不假装成功。

## 3. 恢复语义

1. **先校验**：JSON 可解析 → `format` 正确 → 版本兼容 → 校验和一致 → 基本结构（文档/批注/任务/会话/收藏/设置都是期望的形状）。
2. **再确认**：弹 `alertdialog`，标题写明将覆盖的数量（`覆盖本机数据（N 篇文档 / M 条批注）`），默认危险色；取消不做任何写入。
3. **覆盖式写入**：单事务清空 `docs/marks/tasks/sessions` 后写入备份内容；再写 `meta.bookmarks` 与 `localStorage` 设置。
4. **不整页重载**：写入成功后按备份内容 dispatch（docs/tasks/bookmarks/settings/marks 清空）+ `refreshStats()`，界面立即反映恢复结果。
   - 最初版本用 `location.reload()`，结果 toast 与恢复确认之间的时序在 headless 里不可靠（smoke 抓不到提示），也带来闪屏；改成原地同步。
5. **失败**：事务失败提示 `恢复失败：<原因>`，已写入的部分由事务原子性保证不会半份。

## 4. 为什么不提供 WebDAV

应用**刻意不申请 INTERNET 权限**（离线优先，读的是本机 Markdown，不上传任何内容）。WebDAV 会改变这个安全模型：
- 需要加 `INTERNET` 权限，用户安装时的权限说明会变化；
- 需要存凭据（即使只存本机）、处理证书/超时/冲突；
- 与「可验证的离线」这一核心承诺冲突。

因此本版**明确不做 WebDAV**，在设置页写清「未提供：本应用不申请 INTERNET 权限（离线优先），要加需先改安全模型」，而不是留一个不可用的开关。

## 5. 明确不做（本项内）

- 增量备份 / 多版本历史 / 定时自动备份。
- 选择性恢复（只恢复批注、只恢复设置）——当前是整库覆盖，语义简单且可预期。
- 备份加密（没有用户密码体系；E6 之后再评估）。
- 跨设备同步。
- 生词本字段（依赖 E4）。

## 6. 验收方式

- 单测：`core/backup.test.ts`（生成/解析往返、校验和变更、格式/版本/结构拒绝、排序稳定、空数据统计）。
- smoke：导出 → 从剪贴板读回校验字段 → 从剪贴板恢复 → 确认层 → 恢复成功提示 → 文档仍在；损坏 JSON 被拒绝且不弹确认。
- 截图：`npm run shot:e3`（设置页备份分区、恢复确认层，日/夜两套）。
